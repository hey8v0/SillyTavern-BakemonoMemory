# 剧情事实与做梦：替换剧情状态和表格

状态：设计稿（2026-10-26），尚未实现。目标是用一套"事实卡片 + 做梦"替换现在的剧情状态（rp-core）和表格（tables），和摘要、向量一起组成完整的记忆分层。

## 1. 为什么重做

| 记忆层 | 现状 | 问题 |
|---|---|---|
| 情景记忆（发生过的事） | 剧情摘要 → 阶段总结 → 多次总结 | 可用，保留 |
| 语义记忆（稳定事实） | 剧情状态 + 表格两套并行 | 人物、关系、物品、约定两边各记一份；都在每一轮从原文抽，各自出错 |
| 检索（RAG） | 向量记忆 | 可用，保留 |
| 巩固、反思 | 无 | — |

剧情状态的根本问题是协议：要求模型每轮输出带 id、短引用、原子组的类型化增量（30 多种 action）。模型擅长重写一段描述，不擅长精确输出差分；一条错就整批判"格式问题"。rp-core 约 3500 行、UI 约 1000 行，大部分在防模型出错，用户仍然要逐项纠。用户反馈集中在三点：记错记漏要手动改；注入的内容对写作没帮助；界面看不懂改不动。

表格是另一种每轮抽取（insert/update/delete 单元格），同样的问题，只是形式更松。

## 2. 核心思路

1. **一份数据**：事实卡片。人物、关系、地点、物品、线索（约定/伏笔）、设定、便签。每张卡几个固定字段，字段值是自然语言。没有事件类型、没有 id 协议、没有借还状态机。
2. **不在每一轮上记事实**。最近楼层本来就在上下文里；时间/地点/在场由剧情摘要表头提供（现在也是从那里读的）。
3. **做梦**：每保存一个阶段总结，跑一次巩固。输入是这一阶段覆盖的剧情摘要 + 当前相关卡片，输出是被动到的卡片**整张重写**（按名字对应，不按 id），加一段反思（主线、未回收伏笔、人物弧线）。插件做新旧 diff，自动应用，可撤回；可选先审。
4. **注入**：按当前场景挑相关卡片 + 反思。
5. 旧剧情状态和旧表格一次性导入成卡片，旧数据保留到最后一批再删。

## 3. 数据

挂在聊天状态上：`state.facts`。

```
facts: {
  version: 1,
  revision: 0,                       // 每次应用 +1
  cards: [{
    id,                              // 插件生成，模型不见
    kind: 'person'|'relationship'|'place'|'item'|'thread'|'rule'|'note',
    name, aliases: [],
    fields: { ... },                 // 见下表，值都是字符串，空字符串=未知/不显示
    status: 'active'|'retired',      // retired：已死亡/已了结/已离场，默认不注入
    pinned: false,                   // 固定注入
    updatedAt, updatedBy: 'dream'|'user'|'import',
    userFields: [],                  // 用户改过的字段名；做梦不覆盖，除非剧情明确推翻（diff 里标出）
    sourceStage: null,               // 最近一次更新它的阶段总结 hash
  }],
  reflection: { mainline: '', threads: '', arcs: '', updatedAt: null },
  history: [{ id, at, trigger: 'dream'|'manual'|'user'|'import'|'undo', stageHash, taskId,
              changes: [{ cardId, kind, name, before: fields|null, after: fields|null, status }], reflectionBefore, reflectionAfter }],
  settings: { enabled: false, auto: true, review: false, budgetChars: 6000, maxCardsPerDream: 40, injectReflection: true },
  lastDreamAt: null, lastDreamStage: null,
}
```

字段按类型固定，便于界面和提示词稳定：

| kind | 字段 |
|---|---|
| person 人物 | 外貌、性格、处境（当前状态/位置/伤势情绪）、持有、备注 |
| relationship 关系 | 双方、基础关系、当前关系、态度（甲对乙 / 乙对甲） |
| place 地点 | 描述、常在此处的人 |
| item 物品 | 持有者、描述、意义 |
| thread 线索 | 内容、参与者、状态（未了/已了/失效）、期限 |
| rule 设定 | 说明、影响范围 |
| note 便签 | 内容（只有用户写，模型只读，相当于旧"剧情指导"） |

同名处理：按 `name` 和 `aliases` 匹配（忽略大小写和空白）。模型给出的新名字匹配不到就建新卡；用户可在界面上把两张卡合并（aliases 合并，字段取保留方）。

## 4. 做梦

### 触发

- 自动：`commitDraft` 保存了一条**阶段总结**（kind STAGE）时入队一个 `dream` 任务。多次总结不触发（它是阶段的压缩，不产生新事实）。
- 手动："现在做梦"按钮，标价 `+1 次请求`；可选范围：最近一个阶段 / 指定阶段 / 全部未做梦的阶段。
- 旧聊天补做：按阶段顺序逐个排队，复用现有任务队列。
- 每个阶段只做一次（`history` 里按 stageHash 记录）；阶段总结被重新生成后旧记录标 superseded，可重做。

### 输入

1. 这一阶段覆盖的**剧情摘要**原文（比阶段总结细，且已经过用户确认）。超出预算时退化为阶段总结正文。
2. **相关卡片**：名字或别名在材料里出现的卡片，加上所有 pinned 和 thread 类未了结的卡；上限 `maxCardsPerDream`。没出现的卡片不送，也不会被改。
3. 当前反思。
4. 用户 note 卡只读送入，供理解。

### 输出协议

```
<factCards>
{
  "cards": [
    { "kind": "person", "name": "林晚", "aliases": ["小晚"], "fields": { "外貌": "…", "性格": "…", "处境": "…", "持有": "…", "备注": "" } },
    { "kind": "thread", "name": "码头之约", "fields": { "内容": "…", "参与者": "林晚、沈砚", "状态": "已了", "期限": "" } }
  ],
  "retired": ["旧铜钥匙"],
  "reflection": { "mainline": "…", "threads": "…", "arcs": "…" }
}
</factCards>
```

规则（写进提示词）：只输出有变化的卡，整张写全；没变的不写；不要编造材料里没有的事；用户标注为"用户填写"的字段原样保留，除非材料明确推翻；`retired` 列明确结束的对象。

解析：取标签内 JSON，容忍代码围栏、尾逗号（复用 `tables/operation-parser` 的宽松解析）。整体解析失败 → 任务失败、不动任何数据，可重试。单张卡字段名不认识 → 丢该字段、记入任务提示，不整批失败。

### 应用与审阅

- 默认 `review: false`：直接应用，写一条 history，首页和事实页显示"刚做了梦：改了 N 张卡"，可一键撤回（按 history 逆向写回）。
- `review: true`：进入待确认，草稿类型 `dream`，显示逐卡 diff（新增 / 字段变化 / 结束），可勾选只应用一部分，可改字段后应用。
- 撤回只回退卡片和反思，不动摘要。
- 做梦期间用户编辑了同一张卡：应用时以用户为准（userFields），diff 里标"已保留你的修改"。

### 成本

每个阶段 1 次调用（约每 10 楼），比现在每轮 1 次少。输入约为 10 条剧情摘要 + 几十张卡，输出只含变化的卡。

## 5. 注入

替换现在 `sources.rpState` 和 `sources.table`，新段落：

```
## 剧情事实
人物 林晚：处境 …；持有 …；性格 …
关系 林晚 ↔ 沈砚：当前 …；态度 …
线索 码头之约（未了）：…
## 主线与伏笔
…（reflection）
```

选卡：最近 N 楼（默认 6）正文里出现名字/别名的卡 + pinned + 未了结 thread，按出现次数排序，预算 `budgetChars`。retired 不注入。字段为空不显示。没有卡时不输出该段。注入预览、首页"这一轮注入了什么"、提示词检查器同步改口。

每轮不再有维护指令槽（rpEvents）和表格指令槽（tableEdit）。`inlineGeneration.tableEnabled`、`turnSummary.processingMode` 的 table/both 取消，摘要方式向导去掉表格那一问。

## 6. 迁移

一次性导入，入口在事实页（"从旧剧情状态和表格导入"），也在首次启用时提示：

| 来源 | 目标 |
|---|---|
| rpCore 投影 people / relationships / items / plans / locations | person / relationship / item / thread / place，字段由投影文字拼成；claims/observations 并入相关人物的"备注" |
| 表格 角色特征 / 人物关系 / 世界设定 / 重要物品 / 约定 / 剧情指导 | person / relationship / rule / item / thread / note，列按名字映射 |
| 自定义表格 | 每行一张 rule 卡，字段"说明"为"列名：值"逐行拼接，name 取第一列 |

导入的卡 `updatedBy: 'import'`，建议导入后对最近一两个阶段做一次梦把它们理顺。旧数据（`rpCore`、`tableDatabase`）不删、不再读写，直到第 5 批。

## 7. 界面

一页"剧情事实"，替换"剧情状态"和"表格"两个入口，沿用场记板风格（细线、文字目录、少框）：

- 顶部：反思三段；上次做梦时间 / 下次触发（"再攒 N 条摘要"）；"现在做梦 +1 次请求"；"撤回上次"。
- 目录行：`人物 12 / 关系 5 / 地点 3 / 物品 4 / 线索 2 / 设定 6 / 便签 1`，点切换；搜索框。
- 列表：名字 + 一行摘要；点开为详情，字段可编辑，改过的字段标"你改过"；"固定注入"、"标记结束"、"合并到…"、"删除"。
- 每张卡的"变化"时间线（来自 history），和一次做梦的整体 diff。
- 待确认：`dream` 草稿的 diff 视图（第 2 批）。
- 设置：启用、自动做梦、先审再用、注入预算、反思是否注入、做梦提示词（可编辑、预设，走现有 generationPrompts/预设机制）。

## 9. 分批（每批一个版本）

| 批 | 内容 | 验证 |
|---|---|---|
| 1 | `src/facts/`：数据模型、做梦提示词、输出解析、相关卡选择、应用/撤回、注入段；任务队列加 `dream` 类型；阶段总结保存后自动入队；最简入口（设置里一个开关 + "现在做梦"按钮 + 文本列表）。默认关闭，旧功能不动。 | Node 测试；用户在真实聊天上试做梦，看卡片质量 |
| 2 | 剧情事实页（目录、详情编辑、历史、合并）、待确认的 diff 审阅、撤回。 | 模拟页截图 + 用户实测 |
| 3 | 迁移导入；摘要方式向导、设置中心、首页、注入预览、帮助页改口。 | 用旧聊天的备份包导入核对 |
| 4 | 默认开启；隐藏剧情状态和表格入口（数据保留）；去掉每轮的 rpEvents / tableEdit 槽。 | 全量回归 |
| 5 | 删旧代码、旧测试；备份包升版；文档收口。 | 全量回归、css 死类名清理 |

第 1 批做完就先让用户试，卡片质量不行时改提示词和字段，不要先铺界面。

## 10. 风险

- **模型整张重写的质量**：没有实测过。第 1 批用真实模型验证；不行就调字段粒度或改成"字段级变化"而不是整卡。
- **新鲜度**：事实隔一个阶段才更新。靠最近楼层在上下文里兜底；用户已接受。
- **长档卡片多**：只送相关卡；名字匹配靠文本包含，别名要靠做梦自己维护。
- **用户修改被覆盖**：userFields 保护 + diff 标注；仍可能有误判，撤回兜底。
- **旧用户的自定义表格**：只能导成扁平的设定卡，结构丢失；发版说明要讲清楚。
- **精确规则没有了**（借还、损毁、计划状态机）：这些现在也没真正起作用，换成自然语言。
