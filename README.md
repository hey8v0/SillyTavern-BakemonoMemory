# 剧情剪辑台 / Bakemono Memory

面向 SillyTavern 长篇 RP 的第三方记忆扩展。

当前版本：**v1.4.0**。本版完成工程模块化重构；不迁移记忆数据或配置格式，现有聊天可以直接升级。

剧情剪辑台把散落在聊天里的剧情摘要、阶段总结、长期总览、结构化表格与按需召回整理成一套可检查、可确认、可撤回的记忆工作流。它不只负责“记住”，也尽量让你看清：已经整理到哪里、这一轮实际注入了什么、为什么找回了某段旧剧情，以及哪些内容仍在等待处理。

> 适合几百楼、几千楼的连续剧情，也可以给没有提前制作摘要的旧聊天补课。界面优先为手机端设计，并跟随 SillyTavern 主题；内置暖纸日间、暖纸夜间与高自由度自定义主题。

## 插件能做什么

- 识别聊天中已有的 `<bakemono>` 摘要，建立剧情覆盖关系。
- 把一段段剧情摘要整理成阶段总结，再把多个阶段总结压缩成更长的时间线总览。
- 给没有摘要的旧聊天分批补课，或只补写漏掉摘要的助手楼层。
- 让生成内容先进入“待确认”，检查、编辑或重做后再保存为长期记忆。
- 用表格持续记录角色状态、人物关系、地点、物品、约定与剧情指导。
- 使用本地轻量检索或 OpenAI-compatible Embedding，从旧剧情中按需召回相关原文与摘要。
- 结合向量、关键词和稀有词进行混合召回，并展示命中原因与最终注入结果。
- 自动隐藏已经整理好的旧楼层，降低长聊天上下文与手机渲染压力；原消息不会被删除。
- 在首页查看记忆覆盖、待处理项目、本轮插件注入 Token 构成和当前生效配置。
- 查看 SillyTavern 保存的上一轮完整 Prompt 快照，按条目展开、复制并搜索内容。
- 通过事务记录撤回总结保存、楼层隐藏和表格变更，减少误操作带来的连锁问题。
- 把工作流、扫描、生成、提示词、注入、表格、向量与主题保存为可复用配置。

## 它怎样组织记忆

剧情剪辑台不是把所有旧内容每轮重新塞给模型，而是分层整理：

```text
聊天正文
   ↓ 扫描 / 补课
剧情摘要（短范围、保留细节）
   ↓ 阶段整理
阶段总结（章节级长期记忆）
   ↓ 再压缩
多次总结（跨阶段时间线总览）
```

另外还有两条并行记忆：

- **剧情表格**：保存人物、关系、地点、物品和约定等结构化状态。
- **向量记忆**：从旧正文与摘要索引中找回当前场景真正相关的细节。

最终注入时，插件会按当前工作流组合长期总结、阶段记忆、表格内容、向量召回和模板规则。已被更高层总结覆盖的下级摘要会按策略退出普通注入，尽量避免同一事件反复占用 Token。

## 界面与功能总览

左上角菜单只保留七个一级入口：

| 入口 | 用途 |
| --- | --- |
| **剪辑台** | 只读运行概览：覆盖情况、待处理状态、注入 Token 与当前配置。 |
| **总结** | 生成阶段总结、多次总结，回看结果与摘要树，按需进入批量生成。 |
| **记忆库** | 搜索和筛选已经保存的剧情摘要、阶段记忆与长期总览。 |
| **待确认** | 检查生成草稿、批量任务和近期变更，确认后再写入长期记忆。 |
| **自动与数据** | 管理自动记忆、自动总结、剧情表格和向量记忆。 |
| **设置中心** | 管理工作流、扫描、注入、生成模型、提示词、收纳、主题与整套配置。 |
| **使用说明** | 插件内置的快速开始、推荐流程、功能说明和常见问题。 |

二级页面均提供“返回上一级”入口，手机端不需要反复打开菜单。

## 安装与更新

### 方法一：Git 安装（推荐）

进入 SillyTavern 的第三方扩展目录：

```text
SillyTavern/public/scripts/extensions/third-party
```

在该目录执行：

```bash
git clone https://github.com/hey8v0/SillyTavern-BakemonoMemory.git
```

安装后的目录应为：

```text
SillyTavern/public/scripts/extensions/third-party/SillyTavern-BakemonoMemory
```

以后更新时，在插件目录执行：

```bash
git pull origin main
```

### 方法二：下载 ZIP

1. 在 GitHub 仓库下载 ZIP。
2. 解压到 SillyTavern 的 `public/scripts/extensions/third-party` 目录。
3. 确保插件文件夹内直接包含以下文件，而不是再多包一层目录：

```text
manifest.json
index.js
settings.html
style.css
README.md
```

### 打开插件

刷新或重启 SillyTavern 后，从扩展 / 魔法棒菜单打开“剧情剪辑台”。也可以在扩展设置里开启可选的顶部导航栏入口。

升级前建议备份重要聊天；升级后若仍看到旧界面，请先强制刷新浏览器缓存。

## 三分钟开始使用

1. 打开剧情剪辑台，先看首页是否识别到当前聊天与生效配置。
2. 进入 **设置中心 → 工作流**，按聊天现状选择“已有摘要”“补课旧聊天”或“自定义”。
3. 进入 **设置中心 → 扫描与识别**，扫描当前聊天。
4. 到 **总结** 页面生成第一条阶段总结。
5. 在 **待确认** 中检查标题、时间、角色、事件与结局，确认后保存。
6. 回到首页检查覆盖楼层与本轮注入构成。

第一次使用不必先理解所有参数。生成接口、向量阈值、表格框架和维护工具都可以等真正需要时再展开；插件内的“使用说明”保留了更短的分步教程。

## 按聊天情况选择工作流

### 1. 正文已经带摘要

适合正文结尾已经存在 `<bakemono>` 摘要，并配合酒馆正则隐藏旧正文的聊天。

推荐顺序：

1. 选择“已有摘要”。
2. 扫描摘要块。
3. 摘要积累到一段剧情后生成阶段总结。
4. 确认保存，再按需要收纳已覆盖楼层。
5. 阶段总结积累较多后生成多次总结。
6. 长聊天可建立向量索引，补回被压缩掉的旧细节。

### 2. 旧聊天没有摘要

适合已经玩了很多楼、以前没有使用剧情剪辑台的存档。

推荐顺序：

1. 选择“补课旧聊天”。
2. 在“总结 → 批量生成”中限定一段较小的楼层范围。
3. 选择“旧正文补课”，按批生成插件内摘要。
4. 分批检查并确认，不要第一次就处理几百楼。
5. 再把补课摘要整理成阶段总结。

旧正文补课不会改写原楼层，摘要保存在插件记忆中。

### 3. 只有少数楼漏了摘要

1. 进入“总结 → 批量生成”。
2. 选择“补写缺失摘要”。
3. 指定楼层范围，或留空检查全部候选。
4. 生成并确认后，插件会把标准摘要块追加到对应助手楼层末尾。
5. 重新扫描，确认缺口已经消失。

这是少数会修改原聊天正文的功能；应用前会先进入待确认。

### 4. 需要完全自定义

“自定义”工作流可以组合扫描材料、生成来源和输出规则。建议先跑通一种基础工作流，再调整提示词、上下文来源或自动化规则。

## 功能详解

### 剪辑台：首页运行概览

首页是一张只读“场记单”，不放生成和维护按钮，以免误触或来回跳转。

它会显示：

- 当前聊天的已整理范围、待识别楼层与待确认数量。
- 本轮插件注入 Token 总量。
- 阶段 / 多次总结、长期记忆、表格记忆、向量召回、模板 / 规则各自占用的 Token。
- 插件注入占上一轮完整 Prompt 的比例。
- 当前生效的整套配置、工作流、扫描方式、生成模型、后台整理、注入深度和向量来源。

首页的 Token 来自 SillyTavern 保存的上一轮 Prompt 快照，不用部分聊天伪造“实时估算”。尚未生成过回复，或刚修改了注入配置时，数据可能暂时为空，需要完成下一轮回复后更新。

### 上一轮提示词清单

点击首页“本轮注入”旁的 **查看上一轮**，可以查看 SillyTavern 上一轮实际保存的 Prompt：

- 完整 Prompt
- 基础系统与预设
- 角色卡
- User 人设
- 世界书
- 示例对话
- 聊天记录
- 扩展注入
- 偏置或其他可识别条目

每个条目显示实测 Token，展开时才把长正文插入页面，并支持一键复制。顶部搜索框在输入关键词后点击放大镜（或按 Enter）才执行搜索；结果栏显示当前条目与“第几处 / 共几处”，可以用 ↑ / ↓ 在所有命中位置间循环跳转。插件会自动展开对应条目、把命中片段滚动到正文中央并突出当前结果；搜索不会改写 Prompt，也不会保存聊天数据。

“基础系统与预设”不是把世界书、人设等已经单列的内容再算一次，而是从最终 system / developer 消息中扣除可识别的重叠来源后计算。不同 API 或预设对 Prompt 的组装方式不同，无法完全拆开的内容仍以“完整 Prompt”为最终准绳。

### 扫描与识别

扫描只负责识别当前聊天里“已经有什么”，不会调用生成模型：

- 识别 `<bakemono>` 摘要块。
- 按标签块或分段格式匹配剧情内容。
- 可选择是否扫描隐藏楼层。
- 展示剧情摘要、阶段总结和多次总结的识别数量。
- 为阶段覆盖、记忆档案、自动编排和向量索引提供来源。

长聊天的扫描预览会限制 DOM 数量，完整命中数仍然保留，以降低手机端压力。

### 剧情摘要、阶段总结与多次总结

- **剧情摘要**：保存短范围内发生的事件、时间、地点、人物、动作和冲突，是阶段整理的原材料。
- **阶段总结**：把一段连续剧情整理成可长期使用的章节记忆。
- **多次总结**：把多个阶段总结再压缩为更长跨度的时间线总览。

总结页面支持：

- 手动选择范围生成。
- 按条件批量生成。
- 编辑标题和正文。
- 回看最近结果。
- 通过摘要树查看“剧情摘要 → 阶段总结 → 多次总结”的覆盖关系。
- 在保存前进入待确认。

### 批量摘要与任务队列

批量流程面向旧档和大量缺口，不是日常每轮必用功能。

- **旧正文补课**：把指定范围旧聊天压缩为插件记忆，不修改原正文。
- **补写缺失摘要**：生成标准摘要块并追加回缺失摘要的助手楼层。
- 支持楼层范围、隐藏楼层、每批楼数与任务队列。
- 支持重试失败任务、移除任务和清理卡住的旧任务。

手机端建议从较小批次开始，先确认输出质量，再逐步扩大范围。

### 记忆档案与待确认

**记忆档案**回答“已经保存了什么”：

- 按事件、角色、地点、楼层或正文关键词搜索。
- 按全部、注入中、已归档筛选。
- 查看记忆类型、来源楼层、标签、字数和当前状态。

**待确认**负责“保存前检查什么”：

- 剧情摘要、阶段总结与多次总结草稿。
- 批量生成任务。
- 可编辑、重做、丢弃或确认保存的内容。
- 近期保存与可撤回记录。

### 自动记忆与楼层状态编排

自动记忆可以在正文回复结束后生成摘要、处理表格变化，并按设置把结果保存或交给你确认。

插件会根据现有聊天数据在运行时建立轻量楼层状态索引，判断某楼是否已经有摘要、是否被阶段总结覆盖、是否存在草稿、表格事务、隐藏状态或向量记录，再协调你已经开启的功能：

```text
新回复
→ 判断缺少什么
→ 摘要 / 表格后处理
→ 阶段自动整理
→ 楼层收纳
→ 向量索引刷新
```

编排器不会复制正文，也不会替你开启原本关闭的功能；模型、阈值、保存策略与表格权限仍由各模块自己的设置决定。

### 自动总结

自动总结可以在摘要数量或楼层跨度达到阈值时：

- 只提醒你可以整理。
- 自动生成草稿，等待人工确认。
- 按配置自动保存，并收纳已覆盖楼层。

建议第一次使用先选择“提醒”或“生成草稿”，确认提示词与覆盖范围稳定后，再考虑自动保存。

### 剧情表格

表格用于记录不适合反复写成长篇摘要的结构化状态。

支持：

- 多张自定义表格与多个表格组。
- 全局、角色、当前聊天三种表格框架作用域。
- 只读 / 可写、是否允许 AI 修改、是否注入上下文。
- 手动编辑行列。
- 解析正文中的 `<tableEdit>` 操作。
- 表格修改草稿、自动应用、撤销、重做与事务回退。
- 导入 / 导出表格结构与数据。

内置 **基础表格** 预设包含：

1. 角色特征
2. 人物关系
3. 世界设定
4. 重要物品
5. 约定
6. 剧情指导

它不会重复创建事件摘要或大总结表。新建基础表格组不会覆盖当前自定义表格；同名组已存在时会切换到已有组。

模型输出示例：

```text
<tableEdit>
insertRow(0, {"0":"角色名", "1":"关系", "2":"备注"})
updateRow(0, 1, {"2":"新的备注"})
deleteRow(0, 2)
</tableEdit>
```

### 向量记忆与混合召回

向量记忆用于从长聊天中找回“当前回复真正需要的旧细节”。

支持：

- 本地 fallback 检索，以及 OpenAI-compatible Embedding API。
- 正文索引与摘要索引分开保存。
- 选择是否索引隐藏楼层、用户楼层与最近可见窗口。
- 独立的查询改写模型与提示词。
- 向量候选、关键词候选与用户重点关键词合并。
- 中文 / 英文词项拆分、稀有词加权与最终重排。
- 原文 / 摘要分档召回与 Token / 字符限制。
- 相邻楼层扩展、重复结果过滤与最终注入预览。

“上次召回详情”会展示：

- 原始查询与改写后的检索线索。
- 混合初筛中的向量相似度、词项分数、重点关键词与命中词。
- 最终排序、全文 / 摘要分档与实际注入内容。

本地 fallback 加载轻、适合手机和人名地名等明确词项；它不等同于真正的多语言语义 Embedding。需要更强语义召回时，请配置兼容的外部 Embedding 模型。

### 注入内容

插件使用 SillyTavern 的扩展 Prompt 机制注入记忆，不会把阶段总结反复写回聊天正文。

默认长期记忆模板包含明确的开始与结束边界：

```text
【剧情剪辑台：长期剧情记忆】
以下内容是已经压缩整理过的剧情记忆。请把它当作已发生事实与长期线索参考，不要复述给用户，也不要替代当前回合正文。

{{memory}}
【剧情剪辑台：长期剧情记忆结束】
```

可以调整：

- 是否启用剧情记忆注入。
- 注入位置与深度。
- 长期记忆模板。
- 表格记忆是否注入。
- 向量召回是否注入。
- 各类记忆的包含条件与限制。

已有摘要模式下，普通摘要通常继续由正文正则负责，不重复注入；通用补课模式可临时注入普通补课摘要，被阶段总结覆盖后再退出。

### 楼层收纳

楼层收纳像“隐藏助手”一样管理旧楼层：

- 自动只保留最近 N 楼正文可见。
- 手动输入范围隐藏或恢复。
- 恢复由插件自动收纳的楼层。
- 删除、reroll 或总结回滚后，尽量恢复受影响范围。

收纳是隐藏，不是删除。隐藏前仍建议先确认长期记忆已经正确保存，并保留聊天备份。

### 生成模型与提示词

默认生成模型支持：

- **酒馆主模型**：沿用当前 SillyTavern 连接与模型。
- **自定义 OpenAI-compatible API**：独立填写地址、密钥、模型与流式选项。

阶段总结、多次总结、缺失摘要和旧聊天补课拥有各自提示词。提示词编辑器提供结构预览、复制与恢复默认；自定义提示词会随整套配置保存。

向量 Embedding、查询改写与剧情总结是不同用途，可以分别配置，不必共用同一个模型。

### 外观与自定义主题

插件默认跟随 SillyTavern 主题，并提供：

- 暖纸日间
- 暖纸夜间
- 自定义主题

自定义主题可以修改更完整的颜色、背景、边框、文字和强调色变量，支持保存多套主题、导入与导出 JSON，便于交给 AI 或设计工具继续美化。内置主题受保护，编辑时会另存副本，不会误删原方案。

### 整套配置

整套配置可以保存和复用：

- 工作流与扫描规则
- 自动记忆与自动总结
- 默认生成 API
- 四类生成提示词
- 注入模板与位置
- 表格框架偏好
- 向量接口与召回参数
- 外观与主题

支持保存、另存副本、删除、导入和导出。它只负责设置，不会把某张角色卡的剧情摘要、表格行或向量索引复制到另一张卡。

### 撤回与事务

安全维护集中在设置中心末尾，包括：

- 撤回最近一次总结保存。
- 隐藏 / 恢复楼层事务。
- 表格修改的撤销、重做与级联回退。
- 自动总结保存和自动收纳记录。
- 近期操作轨迹与必要的清理工具。

危险操作仍会先显示确认框；取消后不会产生虚假的成功反馈。

## 配置、API 与数据范围

### 哪些设置对所有角色卡生效

在任意聊天中应用或保存后，以下设置会同步为当前全局活动配置：

- 工作流与扫描方式
- 生成 API 与模型
- 生成提示词
- 注入规则
- 自动化设置
- 表格框架偏好
- 向量接口、模型和召回参数
- 外观主题

切换角色卡或聊天时会自动使用，不需要每次重新拉取配置。

### 哪些数据仍然按聊天隔离

- 剧情摘要、阶段总结与多次总结
- 待确认草稿和任务队列
- 表格数据行与表格事务
- 隐藏楼层记录
- 向量索引、Embedding 缓存与最近召回
- 当前聊天的操作和保存历史

因此“所有角色共用设置”不会把 A 角色卡的剧情记忆注入 B 角色卡。

### API 地址与模型拉取

自定义 API 或 Embedding 接口在拉取模型前会先保存当前输入。即使拉取失败，接口地址、密钥和已填内容也不应因页面刷新消失。

常见兼容地址形态：

```text
https://example.com/v1
https://example.com/v1/embeddings
```

不同服务商对“基础地址”与“完整接口地址”的要求不同，请以服务商文档为准。模型列表拉取失败不一定代表生成或 Embedding 接口不可用，也可能是服务商没有实现模型列表端点；这时可以手动填写模型名。

## Token、API 消耗与手机性能

### 哪些操作不调用生成 API

- 扫描与识别现有摘要
- 查看记忆库、摘要树和提示词清单
- 搜索上一轮 Prompt
- 手动编辑表格或记忆
- 隐藏 / 恢复楼层
- 本地事务撤回

### 哪些操作可能产生额外请求

- 生成阶段总结或多次总结
- 旧正文补课与补写缺失摘要
- 自动记忆 / 自动总结
- 外部 Embedding 建立或刷新索引
- 查询改写
- 使用外部服务测试召回

实际消耗取决于模型、批次、索引范围和自动化设置。第一次使用自动功能前，建议先用一小段聊天确认输出与费用。

### 手机端建议

- 几百楼以上旧档先缩小批量范围和每批楼数。
- 不要同时启动多个大批量摘要、表格处理和向量索引任务。
- 先确认长期记忆正确，再收纳旧楼层。
- 任务卡住时先到待确认检查队列，不要连续重复点击生成。
- 向量索引较大时，优先限制索引范围、最近窗口和结果数量。
- 出现 Termux / WebView 回到启动状态时，先记录操作步骤和任务数量，再刷新；这通常更像移动端内存压力，而不是配置被删除。

插件已把大部分业务操作改为页面级局部刷新，并限制长聊天的预览 DOM 数量，但移动设备的内存上限仍取决于浏览器、Termux、聊天长度和其他扩展。

## 备份、撤回与安全边界

- **升级前**：导出重要聊天，并导出整套配置；表格特别重要时单独导出表格。
- **大批量处理前**：先处理一小段范围，确认提示词与输出格式。
- **隐藏楼层前**：确认摘要 / 阶段总结已保存，并检查注入预览。
- **清空索引前**：向量索引可以从原消息重建，但重建可能再次产生 Embedding 消耗。
- **删除记忆或表格前**：查看影响范围，优先使用撤回 / 事务功能。

剧情剪辑台会尽量提供确认、草稿和回滚，但它不是版本控制系统。聊天正文、角色卡和世界书仍应使用你自己的备份策略。

## 常见问题

### 顶栏显示“注入空”，是不是配置丢了？

不是。“注入空”表示注入功能已开启，但当前没有符合条件的长期记忆。先检查记忆库、待确认、注入预览和扫描结果。

### 换角色卡后为什么不需要重新拉取配置？

从当前版本开始，应用或保存后的工作流、接口、提示词、注入和向量参数会同步给所有角色卡；剧情数据仍按聊天隔离。

### 为什么上一轮“基础系统与预设”可能看起来很大？

不同 API 会以不同方式拼接 system、developer、世界书和预设。插件会扣除可识别的单列来源，但拆分结果只能用于观察；最终实际发送量以“完整 Prompt”为准。

### 为什么“完整 Prompt”没有内容或还是上一轮数据？

提示词清单读取 SillyTavern 保存的上一轮快照。新聊天尚未生成回复、刷新后还没有新请求，或刚修改配置时，都可能暂时没有新的快照。

### 搜索提示词会不会把内容发给 API？

不会。搜索、匹配计数和高亮都在浏览器本地完成，不保存聊天，也不触发生成请求。

### 为什么向量模型列表拉不出来？

先确认接口地址、密钥和来源类型。部分 OpenAI-compatible 服务不提供 `/models`，可尝试手动填写模型；也要确认服务真正支持 Embedding，而不只是聊天补全。

### 本地 fallback 是真正的语义 Embedding 吗？

不是。它是设备要求较低的本地轻量方案，对人名、地点、术语等明确词项更友好；需要跨语言或更抽象的语义匹配时，建议使用外部 Embedding。

### 表格记忆取消注入后为什么还在 Prompt 里？

关闭“表格记忆注入上下文”后会立即保存并重建插件注入。已经保存的上一轮 Prompt 不会被追溯修改，需要完成下一轮请求后查看新快照。

### 删除或 reroll 旧楼层后怎么办？

插件会检查受影响的总结覆盖、表格事务、隐藏记录和向量索引，并尽量标记或回退依赖内容。涉及重要剧情时，仍建议先备份再操作。

### 为什么手机上偶尔很卡？

长聊天、批量生成、外部索引和大量展开内容会叠加内存压力。优先缩小批次、关闭不需要的展开面板、清理卡住任务，并确认没有多个后台功能同时运行。
